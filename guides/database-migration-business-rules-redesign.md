## 6. Rollback

`Down` first runs a guard that **refuses** (raises) when data cannot be represented by the previous schema:
an appointment without a capacity holder, any installation assignment / project beyond `PENDING_ASSIGNMENT`, or a
selection without a `solar_simulation` row. Then it restores `product.image_url` from the primary image, maps statuses back
(PENDING_ACCEPTANCE/ESCALATED → BOOKED, ACCEPTED/COMPLETED → ASSIGNED, ASSIGNED with `acknowledged_at` → ACKNOWLEDGED,
claimed `Pending` → `Assigned`), restores the old checks and the NOT NULL holder, and drops the 8 new tables / 27 columns.
It never re-creates the retained tables (they were never dropped).
**Down stops being available once the new model is used:** a single escalated appointment without a capacity holder
(even if later cancelled) or any installation assignment makes the guard refuse, by design — restore the backup instead. Data written only in the new tables (service areas,
RAG configurations, gallery images beyond the primary, evidence) is lost on Down — export it first if needed.
